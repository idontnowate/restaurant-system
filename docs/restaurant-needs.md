# تحليل احتياجات المطاعم — نظام إدارة شامل

> الهدف: نظام **سهل** يقدر يستخدمه الكاشير والطباخ والمدير بدون تدريب طويل، و**شامل** يغطي كل دورة العمل في المطعم من لحظة الطلب إلى التقارير المالية.

---

## 1. من يستخدم النظام؟

| المستخدم | شنو يحتاج | الجهاز المناسب |
|---|---|---|
| **المالك / المدير** | أرقام المبيعات، الأرباح، تنبيهات المخزون، أداء الموظفين، متابعة الفروع عن بعد | موبايل + كمبيوتر |
| **الكاشير** | تسجيل الطلب بسرعة، الدفع، الطباعة، إغلاق الصندوق | تابلت / شاشة لمس |
| **الويتر (النادل)** | فتح طاولة، أخذ الطلب من الطاولة، إرساله للمطبخ | موبايل / تابلت |
| **المطبخ** | استلام الطلبات بالترتيب، معرفة الوقت، تعليم الجاهز | شاشة مطبخ (KDS) |
| **أمين المخزن** | استلام بضاعة، جرد، تسجيل الهدر | تابلت / كمبيوتر |
| **السائق** | استلام طلبات التوصيل والعنوان والتحصيل | موبايل |
| **الزبون** | منيو QR، طلب أونلاين، نقاط ولاء | موبايل |

---

## 2. الوحدات (Modules) الأساسية

### 2.1 نقطة البيع (POS) ⭐ الأهم
- أنواع الطلب: **صالة / سفري / توصيل / سيارة (Drive-thru)**.
- واجهة لمس سريعة: تصنيفات + أصناف بالصور + بحث.
- **الإضافات والتعديلات** (Modifiers): حجم، بدون بصل، إضافة جبن… مع أسعارها.
- ملاحظات على الصنف أو الطلب كامل.
- خصومات (نسبة / مبلغ) بصلاحية، كوبونات، ضيافة.
- **تقسيم الفاتورة** (بالتساوي / بالأصناف) ودمج الفواتير.
- طرق دفع متعددة: نقدي، بطاقة، محفظة إلكترونية (زين كاش، آسيا حوالة، FastPay…)، آجل، دفع مختلط.
- حساب الضريبة ورسوم الخدمة تلقائياً.
- طباعة فاتورة الزبون + تذكرة المطبخ لكل قسم (مشويات، معجنات، مشروبات).
- **يشتغل بدون إنترنت** ويزامن لما يرجع الاتصال.
- فتح وإغلاق الوردية + تقرير الصندوق (X / Z Report) ومطابقة النقد.

### 2.2 إدارة الطاولات والحجوزات
- مخطط الصالة (قابل للتعديل): أقسام (داخلي، خارجي، VIP).
- حالة الطاولة بالألوان: فارغة / مشغولة / بانتظار الحساب / محجوزة.
- نقل طلب بين الطاولات، دمج طاولات، مدة الجلوس.
- الحجوزات: الاسم، الهاتف، عدد الأشخاص، الوقت، تذكير.

### 2.3 شاشة المطبخ (KDS)
- الطلبات تظهر تلقائياً بالترتيب مع **عداد وقت** (يتلوّن إذا تأخر).
- توزيع حسب المحطة (كل قسم يشوف أصنافه فقط).
- حالات: جديد ← قيد التحضير ← جاهز ← تم التسليم.
- تنبيه صوتي للطلب الجديد، وإشعار للويتر لما يجهز.
- معدل وقت التحضير لكل صنف (للتقارير).

### 2.4 إدارة المنيو
- تصنيفات وأصناف مع صور ووصف وسعر.
- أحجام وإضافات مرتبطة بالصنف.
- **إيقاف صنف مؤقتاً** (نفذ) بضغطة وحدة — يختفي من POS و QR والتوصيل.
- أسعار مختلفة حسب القناة (صالة / توصيل / تطبيقات) أو حسب الفرع.
- عروض و**وجبات كومبو**، وأسعار حسب الوقت (Happy Hour، فطور).
- **منيو QR** للزبون بالعربي والإنجليزي.

### 2.5 المخزون والوصفات (أكبر مصدر للربح/الخسارة)
- المواد الخام بوحدات مختلفة (كغم، غرام، لتر، قطعة، كرتون) مع التحويل بينها.
- **وصفة لكل صنف** (Recipe): شاورما = 150غ دجاج + خبز + صوص… → خصم تلقائي من المخزون عند البيع.
- **تكلفة الصنف** تتحسب تلقائياً ← نسبة تكلفة الطعام (Food Cost %).
- حد أدنى لكل مادة + تنبيه عند النقص.
- الجرد الدوري ومقارنة (المتوقع × الفعلي) لكشف الهدر والسرقة.
- تسجيل الهدر والتالف مع السبب.
- الموردين، أوامر الشراء، استلام البضاعة، الديون للموردين.
- التحويل بين المخازن / الفروع، وتتبع تاريخ الانتهاء.

### 2.6 الموظفين والصلاحيات
- أدوار جاهزة: مدير، كاشير، ويتر، طباخ، سائق، أمين مخزن — مع صلاحيات دقيقة (مثلاً: الكاشير ما يقدر يلغي فاتورة بدون رمز المدير).
- دخول سريع بـ **رمز PIN** على جهاز الكاشير.
- الحضور والانصراف، جدول الورديات.
- الرواتب، السلف، الخصومات، والإكراميات.
- **سجل العمليات** (Audit Log): مين ألغى، مين خصم، مين فتح الدرج.

### 2.7 العملاء والولاء (CRM)
- ملف الزبون: الاسم، الهاتف، العناوين، تاريخ الطلبات، المفضلات.
- نقاط ولاء / كاش باك، كوبونات، عروض عيد الميلاد.
- رصيد آجل للزبائن الدائمين والشركات.
- تقييمات وملاحظات بعد الطلب.
- رسائل SMS / واتساب تسويقية.

### 2.8 التوصيل
- مناطق التوصيل مع رسوم وحد أدنى لكل منطقة.
- تعيين السائق، تتبع الحالة، تحصيل نقدي من السائق وتسويته.
- استقبال طلبات التطبيقات (طلبات، توترز، لزّة… حسب السوق) في شاشة وحدة.
- موقع طلب أونلاين خاص بالمطعم (بدون عمولة).

### 2.9 المالية والتقارير
- **لوحة تحكم لحظية**: مبيعات اليوم، عدد الطلبات، متوسط الفاتورة، الطاولات المشغولة.
- تقارير المبيعات: باليوم/الساعة/الصنف/التصنيف/الموظف/القناة/طريقة الدفع.
- **الأصناف الأكثر والأقل مبيعاً وربحاً** (Menu Engineering).
- ساعات الذروة (لتنظيم الورديات).
- المصاريف (إيجار، كهرباء، مولدة، رواتب) ← **صافي الربح الحقيقي**.
- الضرائب، الإلغاءات، الخصومات، الهدر.
- تصدير Excel / PDF، وإرسال تقرير يومي تلقائي للمالك.

### 2.10 الفروع المتعددة
- إدارة كل الفروع من حساب واحد، منيو مركزي مع استثناءات لكل فرع.
- مقارنة أداء الفروع، مطبخ مركزي يوزع على الفروع.

### 2.11 الإعدادات
- بيانات المطعم والشعار، العملة (دينار عراقي / دولار مع سعر صرف)، الضريبة والخدمة.
- الطابعات (فواتير / مطبخ) وأجهزة الدرج النقدي.
- تصميم الفاتورة، اللغة، النسخ الاحتياطي.

## 3. متطلبات غير وظيفية (تفرق بين نظام ناجح ونظام مهجور)
1. **السرعة**: تسجيل طلب عادي بأقل من 10 ثواني.
2. **السهولة**: أزرار كبيرة، ألوان واضحة، أقل عدد خطوات، عربي RTL أصلي.
3. **العمل بدون إنترنت** (ضروري جداً مع انقطاعات النت والكهرباء).
4. **الأمان**: صلاحيات، سجل عمليات، نسخ احتياطي سحابي.
5. **يعمل على أي جهاز**: تابلت، كمبيوتر، موبايل.
6. **الدعم ثنائي اللغة** للفواتير والمنيو.

## 4. خطة البناء المقترحة (مراحل)

| المرحلة | المحتوى | ليش بهذا الترتيب |
|---|---|---|
| **1 — MVP** | POS + المنيو + الطاولات + شاشة المطبخ + لوحة تحكم بسيطة + الموظفين/الصلاحيات | هذا اللي يشغّل المطعم يومياً |
| **2** | المخزون والوصفات + الموردين + التقارير المفصلة + إغلاق الوردية | يكشف الربح الحقيقي والهدر |
| **3** | العملاء والولاء + التوصيل + منيو QR + الطلب أونلاين | يزيد المبيعات |
| **4** | الفروع المتعددة + تكامل تطبيقات التوصيل + تطبيق المالك | للتوسع |

## 5. التقنية المقترحة (للنقاش)
- **الواجهة**: React (أو Next.js) كتطبيق ويب PWA يشتغل على كل الأجهزة ويدعم العمل بدون إنترنت.
- **الخادم**: Node.js (NestJS) أو Laravel.
- **قاعدة البيانات**: PostgreSQL على السيرفر + تخزين محلي (IndexedDB/SQLite) للعمل بدون نت.
- **الوقت الحقيقي**: WebSockets لربط الكاشير ↔ المطبخ ↔ الويتر.
- **تطبيق الموبايل** (لاحقاً): React Native أو Flutter.
